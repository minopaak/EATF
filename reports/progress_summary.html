Cross-Domain Event-Aware TS Benchmark

EATF Dataset
왜 · 어떻게 · 무엇을 만들었나

Multimodal 시계열 모델이 "이벤트를 이해"하는지 진단할 수 있는 벤치마크.
이해를 세 조건 (a) Locality · (b) Generalization · (c) Reasoning over retrieval 로 정의하고, 각각을 측정 가능한 결과물로 만든다.

Phase 1 데이터 구축 + 파이프라인 검증 완료 · Phase 3 ROI 라벨링 대기

01왜 만드나 — 진짜 이해인가, in-distribution shortcut인가

VoT, Time-LLM 등 최근 multimodal 모델이 in-domain에서 unimodal을 일관되게 이긴다. 그러나 두 가설이 in-domain 관측만으로는 구분되지 않는다.

가설 A — 진짜 이해

이벤트의 의미를 도메인-agnostic하게 표현. 학습 시 안 본 도메인에서도 텍스트가 도움이 됨.

가설 B — in-distribution shortcut

학습 corpus의 (텍스트, 시계열) co-occurrence에 의존하는 mapping. 분포 안에선 잘 작동, 밖에선 보장 없음.

  • 핵심 문제 — 두 가설은 in-domain 평가에선 관측상 동일. 분포 밖에서만 갈라진다.
  • 현 평가의 한계 — Time-MMD, CiK, VoT 평가 어느 것도 이 분리를 강제하지 않음.
  • 그래서 — 두 가설을 구분할 수 있는 진단 도구가 필요하다.

02이벤트 이해의 정의 — 세 조건 (a)(b)(c)

진짜 이해라면 다음 셋을 모두 만족해야 한다. 셋 중 하나라도 실패하면 in-distribution shortcut에 가깝다.

(a) Locality

이벤트가 영향을 주는 구간(ROI)을 식별. "어디서" 이벤트가 작동하는지 안다. 전 구간 평균 MSE만으로는 가려진다.

(b) Generalization

학습 시 안 본 도메인의 이벤트에도 텍스트가 도움이 된다. 도메인-agnostic 표현이 있다.

(c) Reasoning over retrieval

시계열 perturbation에도 텍스트 우위가 살아남는다. 학습 corpus 직접 retrieval이 아니다.

세 조건의 conjunction. 모두 통과해야 "이해"라고 부른다.

03현재 방법들은 무엇을 학습하나

접근대표메커니즘한계
Case-based retrieval VoT-HIC, FNF (텍스트, 시계열 trajectory) KB → 유사 case retrieve (텍스트, 시계열) 매핑 자체가 도메인 의존
LLM-conditioned Time-LLM 사전학습 LLM 표현으로 시계열 모델 조건화 LLM ↔ 시계열 mapping은 학습 corpus에서 end-to-end
Architectural fusion MM-TSFlib, DualTime cross-attention 등으로 결합 fusion 패턴 자체가 학습 분포 의존
셋 모두 학습 corpus의 텍스트-시계열 co-occurrence 위에서 동작 → in-distribution shortcut. 분포 밖 보장 없음. "암기"가 아니라 분포 의존적 mapping의 학습.

04그래서 만든 것 — 진단 ↔ 결과물 1:1 매핑

EATF는 (a)(b)(c)를 자연 텍스트 위에서 동시에 측정 가능하게 만든 진단 도구. 각 진단은 구체적 결과물에 대응된다.

진단결과물측정 metric
(a) Locality ROI 라벨
LLM duration → CPD validation (IoU≥0.5) → human adjudication		 ROI MSE vs non-ROI MSE
(b) Generalization text-knowledge-transfer protocol
1→4, target TS 고정 · source 텍스트만 swap		 Cross-domain degradation ratio
(c) Reasoning over retrieval memorization-controlled splits
CiK 방식 clean / additive-noise variants		 clean ↔ noise gap
셋 모두 통과해야 "이해". 어느 하나라도 떨어지면 그 모델은 in-distribution shortcut에 가깝다.

07파이프라인 검증 — Time-MMD 베이스라인 재현

우리 코드를 MM-TSFlib의 자기 데이터 CSV에 그대로 돌려 논문 수치 재현 시도. 결과는 명확하다.

  • Traffic ✅ — DLinear / PatchTST 모든 horizon에서 논문과 정확 일치 (0.35 / 0.21 등).
  • SocialGood ✅ — 우리 데이터에서도 MM 데이터에서도 모두 일치 (데이터 vintage 무관).
  • Economy ✅ (조건부) — 우리는 시간순 정렬이라 0.27, MM의 원본 내림차순 정렬을 그대로 따라하면 논문값 0.02 재현. → 논문 Economy 0.02는 미정렬 input artifact로 확정.
결론: 우리 파이프라인은 정확. 잔여 차이는 데이터 vintage(과거 확장 여부) · 정렬 정책 · 다채널 평가 metric 차이로 설명 가능. 우리 수치가 baseline의 "깨끗한" 버전.
